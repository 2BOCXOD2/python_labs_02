# Лабораторная работа №7

## 1. Цель работы и что было реализовано
### Цель работы - обобщить всё, что бвыло сделано за семестр и превратить это в удобное cli приложение, с которым можно легко и интуитивно понятно взаимодействовать
### Реализовано консольное приложение cli для управления коллекцией транспортных средств. В работе применены принципы объектно-ориентированного программирования (наследование, полиморфизм), структурная типизация через Protocol, паттерн "Стратегия" для сортировки и фильтрации, поиск по имени или ччасти имени, реализовано удобное меню, красивый вывод, сохранение коллекции и её загрузка при последующем запуске

## 2. Структура проекта, описание файлов и их назначения, что за что отвечает
### app.py         - Бизнес-логика. Содержит класс TransportApp, который управляет коллекцией и реализует операции: добавление, удаление, поиск, фильтрация и обрабатывает бизнес-правила.
### cli.py         - Интерфейс командной строки. Отвечает только за отображение меню, ввод данных пользователем и вывод результатов. Не содержит бизнес-логики.
### exceptions.py  - Собственные исключения для ошибок предметной области
### main.py        - Точка входа
### models.py      - Классы предметной области (Transport, Car, CargoShip, Airplane). Описывают данные и базовое поведение объектов.
### storage.py     - Логика сохранения и загрузки данных в JSON-файл.

## 3. Описание CLI
### В меню реализованы пункты:
### 1. Добавить транспорт            - создание и добавление нового объекта в коллекцию.
### 2. Показать весь транспорт       - вывод всех объектов в виде форматированной таблицы.
### 3. Найти транспорт по названию   - поиск по части названия.
### 4. Фильтровать по цене           - отбор объектов, цена которых попадает в заданный диапазон.
### 5. Удалить транспорт             - удаление объекта по названию с подтверждением операции.
### 6. Сортировать коллекцию         - сортировка по названию, цене или дате добавления.
### 0. Выход                         - выход из приложения

## Обработка ошибок:
### Ввод данных: ввод нечислового значения там, где ожидается число, перехватывается и выводится сообщение об ошибке.
### Бизнес-логика: попытка добавить дубликат или удалить несуществующий объект вызывает собственные исключения (DuplicateItemError, ItemNotFoundError) и выводит сообщение.


## Сохранение и загрузка:
### Автосохранение: при выборе пункта "Выход" данные автоматически сохраняются в файл data/transports.json.
### Автозагрузка: при запуске приложения программа автоматически пытается загрузить данные из этого же файла. Если файл не найден, коллекция создаётся пустой.
### Формат: данные сохраняются в формате JSON, где для каждого объекта хранится его тип и набор атрибутов.

## Что было изучено:
### Разбиение на модули и слои: реализация строгой трехслойной архитектуры (Presentation Layer / Business Logic Layer / Data Access Layer) для разделения ответственности между файлами.
### CLI-интерфейс: создание интерактивного взаимодействия с пользователем через консоль, включая обработку пользовательского ввода.
### Обработка исключений: разработка собственных исключений для предметной области (ItemNotFoundError, DuplicateItemError) и их использование для контроля хода выполнения программы.
### Работа с файлами и типизация (для оценки 5): реализация сериализации и десериализации данных в формат JSON. Применение аннотаций типов (type hinting) во всем коде для повышения его надежности и читаемости.
